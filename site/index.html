Calibrated decisions you can actually trust

Define the policy once — model, isotonic calibration, risk bands and reason codes — and every applicant comes back with a consistent, explainable, auditable decision. No drift between analysts, no surprises at review.

# single source of truth — versioned
model: gbm_pd_v4 # AUC 0.795
calibration: isotonic
output: pd # calibrated PD [0,1]
bands: # PD cutoff → grade

C: { max_pd: 0.15, decision: REFER }
D: { max_pd: 0.30, decision: REFER }

FAQ

Questions, answered

Everything you need to know about how the engine scores, explains, and governs every credit decision.

01What is an AI-native credit decision engine?
It’s a decisioning system with a calibrated machine-learning model at its core — not a static rules table. You upload applicant data and it returns a probability of default, an A–F risk grade, and an APPROVE / REFER / DECLINE decision with reason codes and a written credit memo — in roughly 6ms per score, with no manual scorecard maintenance.
02How is this different from a traditional scorecard?
A traditional scorecard relies on fixed weights and manually binned variables that drift out of date and require analyst rebuilds. The engine learns non-linear interactions directly from data while preserving the transparency lenders expect — surfacing per-applicant reason codes and a plain-language rationale. You get higher discrimination (AUC 0.795, Gini 0.590) without giving up explainability.
03Is every decision explainable?
Yes — every score ships with ranked reason codes that quantify each factor’s contribution to the PD, an AI-written credit memo summarizing the rationale, and adverse-action language for declines. Nothing is a black box: a reviewer can trace exactly why an applicant was approved, referred, or declined before the decision is finalized.
04What data can it score?
Any CSV — messy real-world exports included. The engine auto-cleans the file on ingest: it infers types, normalizes column names, handles missing values, and maps your fields to model features without manual templating. Drop in a raw applicant export and it scores the whole batch in seconds.
05How accurate and calibrated is it?
The model reaches an AUC of 0.795 with KS 0.445, and predicted probabilities are isotonically calibrated — so a stated 5% PD genuinely means roughly 5 in 100 default, with a measurable Brier-score improvement over the raw output. These figures are illustrative, produced on synthetic data; revalidate against your own portfolio before relying on them. Isotonic-calibrated PD
06Is it governed and compliance-ready?
It’s built for oversight: every decision is logged to an immutable audit trail, models are versioned, and human review can be required before any outcome is committed. Fairness checks run across segments to surface disparate impact early. As with any model, complete your own validation, documentation, and revalidation before deploying to production.

How it works

Built like a regulated model, not a notebook

Every applicant flows through the same governed pipeline, and every decision is explainable and logged.

📊

Calibrated PD

Isotonic calibration means a "5% PD" really means ~5 in 100 — essential for pricing and expected-loss.

🔍

Reason codes

SHAP / linear contributions surface the factors behind each decision, supporting adverse-action explanations.

🧹

Auto-clean intake

Any CSV — odd headers, £/%/text, gaps — is mapped, coerced, imputed and clipped before scoring.

🧑‍⚖️

Human-in-the-loop

A decision margin routes borderline and declined cases to a human. The LLM narrates — it never decides.

📈

Dashboards + PDF

Grade, decision, PD and risk-vs-DTI charts, plus a one-click PDF report for credit committee.

✅

Tested & CI'd

21 unit tests, GitHub Actions, Docker + compose. Graceful fallbacks so it runs anywhere.

Run it

The full FastAPI + Streamlit app

This page is a static export. To run the real service with the API, Swagger docs and monitoring dashboard:

cd credit-risk-engine
pip install -r requirements.txt
make train      # generate data, train + register a model
make app        # Streamlit UI  -> http://localhost:8501
make api        # FastAPI docs  -> http://localhost:8000/docs
# or: docker compose up --build
